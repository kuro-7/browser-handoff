# iPhone 実機確認の手順（チェックリスト）

iPhone を手に持って、上から順に進めるための手順。1回の実機確認で、A（アプリ内ブラウザ → 通常のブラウザ）の iOS の動きと、B1（Safari → ホーム画面アプリ）をまとめて確かめる。使うのはデモページ（[`demo/README.ja.md`](../demo/README.ja.md)）。何を確かめるかの背景は設計書（[`design.ja.md`](design.ja.md)）の 4章と 8章。

- 結果は各表の空いた欄に書く。○（できた）・×（できなかった）・△（条件つき）と、気づいたことを短く。
- デモの記録は自動でサーバーに送られる。終わったあと開発者が `npm run logs -- --ua iPhone` で読むので、表に書ききれない細かいこと（合図が何 ms で来たか、券の頭4文字など）は書かなくてよい。
- 気づいたことは、デモの「見たこと」のボタンか「メモを残す」でも記録に残せる。アプリの版はメモに書くと記録と並ぶ。
- アカウント名は、表にもメモにも書かない（「自分宛ての DM」のように書く）。

## 2. ボタンで外のブラウザを開く（A1、ふだん使いは Safari）

設計書 4章の経路 A1。アプリごとに、次の 1〜6 を繰り返す。

1. アプリの中でデモの URL を押し、アプリ内ブラウザで開く
2. いちばん上の表示を見る。「（アプリ名）のアプリ内ブラウザ」なら正しい
   - 「通常のブラウザ（Safari）」と出たら判定違い（iOS の X は Safari と同じ名乗りの画面を使うと言われている）。その下の「アプリの中で開いているのに『通常のブラウザ』と出たとき」を開き、アプリを選んで「アプリ内ブラウザとして扱う」を押す
3. 大きなボタン（「Safari で開く」または「外のブラウザで開く」）を押す
4. 開く前に確認の画面が出たら、文言を表に書き、進む方を押す。アプリに戻ったときに「見たこと」の「開く前に確認が出た」を押す
5. 開いた先のいちばん上に、どのブラウザかが出る（「通常のブラウザ（Safari）」など）。「受け取り」に「届きました」が出れば成功
6. アプリに戻る。アプリ内ブラウザが残っていれば、デモの表示が「届きました」になっているか見る（戻ったときの照会）

| アプリ | 上の表示（判定） | ボタンの文言 | 確認の画面（文言） | 開いたブラウザ | 届いたか | 戻ったときのアプリ内ブラウザ |
|---|---|---|---|---|---|---|
| X | | | | | | |
| LINE | | | | | | |
| Instagram | | | | | | |

## 3. アプリのメニューから開く（A2）

設計書 4章「アプリのメニュー」の iOS の列が今の版と合っているか。アプリごとに次を繰り返す。

1. アプリの中でデモを開き、「詳しい情報・切り替え」→「開き方を変える」を「手段なし（メニューから開く練習）」にする
2. 大きなボタン（「ブラウザで開く方法を見る」）を押す。ページが読み込み直されて、メニューの案内が出る
3. 案内のとおりにアプリのメニューから開く。違っていたら、実際の場所を表に書き、「見たこと」の「メニューの場所が違った」を押す

5. アプリに戻り、アプリ内ブラウザが残っていれば、数秒で「届きました」に変わるか見る（設計書 4章「メニューから移ったときも、戻ったら確かめる」。閉じずに残るアプリでは未確認）
6. 開き方を「自動（今の場所の方法）」に戻す

| アプリ | 案内に出たメニュー | 実際のメニューの場所と項目名 | 開いたブラウザ | 届いたか | 戻ったとき |

## 4. ふだん使いを Chrome にして、どのブラウザが開くか

iOS の既定の開き方（`planEscape` の iOS。設計書 4章「iOS の Chrome」と、PR [kuro-7/browser-handoff#4](https://github.com/kuro-7/browser-handoff/pull/4) の「iOS で『ふだん使いのブラウザ』を開けるか」）を見直すための結果。

- [ ] 設定 → アプリ → デフォルトのブラウザ を Chrome にする
- [ ] Chrome でデモを一度開き、いちばん上が「通常のブラウザ（Chrome）」になるのを見ておく

アプリごとに、ボタン（開き方は「自動」）とメニュー（開き方は「手段なし」）の両方を試す。手順は 2章・3章と同じ。

| アプリ | ボタンで開いたブラウザ | ボタンで届いたか | メニューの項目名（Chrome 派のとき） | メニューで開いたブラウザ | メニューで届いたか |
|---|---|---|---|---|---|
| X（`x-safari-https`） | | | | | |
| LINE（`openExternalBrowser=1`） | | | | | |
| Instagram（`instagram://extbrowser`） | | | | | |
| Threads（`barcelona://extbrowser`） | | | | | |

- メニューの項目名が「Safari で開く」から「ブラウザで開く」などに変わるかも書く
- [ ] 終わったら、デフォルトのブラウザを Safari に戻す

## 5. アプリ内ブラウザのバーとページの寸法

設計書 4章「アプリ内ブラウザのバーとページの寸法」の表を iOS でも埋める。アプリごとに次を繰り返す。

1. アプリの中でデモを開き、「画面の寸法を測る」→「測る」を押す（ページが読み込み直される）
2. 右上の枠に値が出る。そのまま画面の写し（スクリーンショット）を1枚撮る
3. 上下にスクロールして、アプリのバーが隠れたり出たりするか見る。隠れたら、隠れた状態でもう1枚撮る
4. 「viewport-fit=cover を外して読み込み直す」を押し、もう1枚撮る（値が変わるか）
5. 画面の写しで、次の線が、アプリのバー（下のボタン列や帯）のどこに来ているかを見る。左端の目盛りは上から 50px ごと
   - 赤（`position: fixed; bottom: 0`）
   - 緑（`bottom: env(safe-area-inset-bottom)`）
   - 青（`100vh` の下端）
   - 真ん中の短い橙（`100dvh` の下端）
6. 「測るのをやめる」を押す

| 開いた場所 | バー（上・下、スクロールで隠れるか） | safe-area-inset（上下左右） | innerHeight（バーが出ている／隠れた） | 100vh・dvh・svh・lvh | 赤・緑・青・橙の線の位置（バーとの関係） | cover のありなしで変わったか |
|---|---|---|---|---|---|---|
| X のアプリ内ブラウザ | | | | | | |
| LINE のアプリ内ブラウザ | | | | | | |
| Instagram のアプリ内ブラウザ | | | | | | |
| Threads のアプリ内ブラウザ | | | | | | |
| （比べる用）Safari | | | | | | |

値は記録にも残るので、表には目立つ違いだけ書けばよい。画面の写しは、あとで開発者に渡す（アカウント名や他の人の投稿が写っていたら、その部分は塗るか切る）。

## 6. Safari からホーム画面アプリへ（B1）

設計書 4章の経路 B1。iOS の Safari で `<link rel="manifest">` を券付きの URL に差し替え、ホーム画面に追加したアプリが、その manifest の `start_url`（券入り）で開くかを見る。ふだん使いは Safari に戻してから。

ホーム画面のアイコンは、追加するときの名前を変えて見分ける（追加の画面で名前を書き換えられる）。

### 6-1. 手順を出す時に差し替えた場合（ボタン）

1. Safari でデモを開く。「ホーム画面に追加」の「ホーム画面用の券を用意する」を押す
2. 「用意できました」の「中身」を開き、券の頭4文字を表に書く
3. 共有 →「ホーム画面に追加」。名前を「HS-ボタン」にし、「Webアプリとして開く」がオンなのを確かめて追加
4. 追加したアイコンから開く。いちばん上が「ホーム画面アプリ」、受け取りが「届きました」、起動 URL が「manifest の start_url で開いた」なら成功

### 6-2. 読み込み時に用意した場合

1. Safari でデモを開き、「詳しい情報・切り替え」→「ホーム画面に追加」の「ページを開いたときにホーム画面用の券を自動で用意する」をオンにする
2. Safari でデモを読み込み直す（ボタンは押さない）。数秒待つ
3. 共有 →「ホーム画面に追加」。名前を「HS-読込」にして追加
4. 追加したアイコンから開いて、6-1 と同じく見る
5. 「自動で用意する」をオフに戻す

### 6-3. 翌日以降に初めて開く

1. 6-1 の 1〜3 と同じ手順で、名前を「HS-翌日」にして追加する。**追加したあと、このアイコンは開かない**
2. 翌日以降に、パソコンで `npm run demo:on` してデモを開け直す
3. 初めてアイコンから開いて（日付と時刻を表に書く）、6-1 と同じく見る
4. 確かめ終わったら、すぐ `npm run demo:off`

### 6-4. start_url が使われなかったときだけ

6-1・6-2 で起動 URL が「start_url ではない URL で開いた」になったら、iOS が manifest の `start_url` を使わず、追加したときのページの URL で開いている。代わりの方法（ページの URL に券を付けておく）で届くかを試す。

1. Safari でデモを開き、「詳しい情報・切り替え」→「ホーム画面に追加」の「用意したとき、ページの URL にも券を付ける」をオンにする
2. 「ホーム画面用の券を用意する」を押す（アドレスバーの URL に券が付く）
3. 共有 →「ホーム画面に追加」。名前を「HS-URL」にして追加し、開く
4. 起動 URL が「追加したときのページの URL で開いた」で「届きました」なら、この方法なら届く
5. オンにした項目をオフに戻す

| 試したこと | 券の頭4文字 | 追加した日時 | 初めて開いた日時 | 上の表示 | 起動 URL | 受け取り | ID（Safari と同じか） |
|---|---|---|---|---|---|---|---|
| 6-1 ボタン | | | | | | | |
| 6-2 読み込み時 | | | | | | | |
| 6-3 翌日以降 | | | | | | | |
| 6-4 URL に券（必要なときだけ） | | | | | | | |

- アイコンを2つ以上追加したら、アイコンごとに ID が違うか（ホーム画面アプリどうしで保存場所が別か）も表の最後の欄で分かる
- 2回目以降にアイコンから開いたときは、受け取りが「届きました（もう同じアカウント）」か何も出ないのが正しい（設計書 5章の `notifiedBefore`）

## 7. iPhone のホーム画面アプリはリンクを引き取らない

Android では、ホーム画面に追加したアプリ（WebAPK）が、そのサイトのリンクを引き取った（設計書 4章「X のリンクも、ホーム画面アプリが引き取る」）。iPhone では起きないはず（未確認）。6章のアイコンが残っている状態で確かめる。

| リンクを押した場所 | 開いた場所（デモのいちばん上の表示） |
|---|---|
| X | |
| LINE | |
| Instagram | |
| Threads | |
| Safari のアドレスバーに URL を入れる | |
| メモ帳などのアプリのリンク | |

どれも「ホーム画面アプリ」ではなく、アプリ内ブラウザや Safari が開けば、Android と違って引き取らない（予想どおり）。
